# PACE ATLAS｜兩場賽事，一眼比較

網站：https://williamslchang-blip.github.io/ironman-course-predictor/

## 第三版使用流程

- 左欄：過往最佳賽事名稱、51.5／113／226 組別、游泳、T1、騎車、T2、跑步及總時間。五項必須來自同一場，總時間差超過 2 秒要求核對。
- 右欄：預計賽事名稱、組別與樂觀／中性／悲觀的各分項、配速及總時間。
- 兩欄都可以搜尋場次，或直接貼上公開賽道網頁／PDF 網址。
- 查詢結果需核對年份、來源及數值，採用後再執行預估。更改場次／組別會使已讀資料失效，必須重新讀取或確認手動條件。
- 公式、兩場賽道比較、游騎跑攻略及進階條件收進「說明與賽道分析」，主畫面不放長篇說明。
- 保留本機儲存、舊版設定遷移、CSV、列印與自行車 GPX 匯入。

## 連網資料

### 場次查詢

使用 metrica.fit 公開 API：https://www.metrica.fit/developers 。支援其已收錄的 IRONMAN／70.3，沒有涵蓋所有 51.5 或歷年賽事。此來源屬第三方彙整，非官方保證。氣候是多年典型值，不是實測或即時預報。推算 GPX 距離不會默默覆蓋組別距離，須由使用者明確選擇。來源未提供的浪況、水流、濕度、技術性等不會從自動摘要臆測。

### 公開網址讀取

使用 Jina Reader：https://jina.ai/reader/ 。將使用者指定的公開網址轉為文字，再按分項與距離／爬升標記擷取數值。不是大語言模型自由補完資料。補給點、關門時間及途中里程會盡可能排除；多個候選值須人工選定。數值缺漏、圖片地圖、掃描 PDF、網站限制、限流或網路中斷都可能導致無法匯入，並會顯示待補或錯誤。來源文字只作資料，不作程式指令。

兩種讀取方式都不保證路線年份。缺少或不符年份時，使用者需自行核對並確認。無法讀取時可使用手動資料；自訂預估要求兩場均採用資料或明確確認手動條件，避免將示範路線當成真實賽道。

## 模型與隱私

沿用公開的 2.0 經驗模型：各項距離冪次換算，再比較兩場浪況、水流、防寒衣、爬升、風曝露、路面、技術性及熱負荷。係數尚未以選手賽績校準；三種情境不是機率或信賴區間。單場短距離成績不能驗證長距離耐力。

成績、選手代號及 GPX 在瀏覽器處理，不傳送至查詢服務。賽事 API 接收讀取請求；Jina Reader 接收使用者要求讀取的公開網址。按儲存才寫入 localStorage。公開儲存庫不包含個人輸入。網站為 GitHub Pages 靜態前端，無金鑰、無追蹤碼或外部執行程式；連網功能依賴上述服務的可用性。

## 驗證

- node --check app.js
- node --check lookup.js
- node --check course-data.js
- node model.test.js
- node course-data.test.js
- node qa-dom.cjs

DOM 測試使用獨立 jsdom 安裝，Windows 預設從 TEMP/pace-atlas-qa/node_modules/jsdom 讀取；其他環境可設定 PACE_ATLAS_QA_ROOT。涵蓋九種距離轉換、兩欄操作、可選說明、網址解析、來源核對、年份確認、推算距離保護、舊賽道失效、網路錯誤、儲存／遷移與 GPX。DOM 及 CSS 解析測試不能代替真實瀏覽器目視檢查。

已另以公開 API 完成實際連線測試，並以官方 2025 Kenting 英文選手手冊測得游泳／自行車／跑步總距離。圖像式 Czech 賽道頁未讀到數值，保持未提供，不以預設值冒充擷取結果。
